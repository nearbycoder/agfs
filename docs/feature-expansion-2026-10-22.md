## Browser: prepare data and documents

Open **File tools → Prepare** at `/app/tools`. The three workspaces are **Prepare JSON records**, **Prepare & reconcile tables**, and **Review documents for handoff**. Select a task, paste inputs or explicitly load a file, configure it, then click **Generate preview**. Each task also appears by its displayed name in the command palette; append its table hash to `/app/tools` for direct navigation. The [catalog](../apps/web/src/lib/browser-feature-catalog.ts) and [workbench](../apps/web/src/components/platform/DataPreparationWorkbench.tsx) define these entry points.

All 17 transformations run locally on explicit preview, with **zero server transform requests**. Optional workspace loads and saves use the network. Results can be copied, downloaded or saved through the existing create-only uploader; supported JSON/CSV results can become the next input. Input/task changes clear obsolete previews, and an active save locks the relevant controls until its outcome is known.

Browser JSON preserves exact number tokens, compares equivalent decimals without binary64 rounding, and rejects duplicate object keys. Missing and null differ; grouping/sorting require present scalar keys and indexing requires unique strings. JSON Patch refuses root removal and returns no partial result after a failed operation. The record contract is a small required-field/type rule set, **not full JSON Schema**.

CSV requires unique nonempty headers and consistent widths. Numeric sorts reject invalid or empty numbers; sums enforce normalized exponents within ±1,000 and a 2,048-digit working limit. Export prefixes formula-like cells, including leading-whitespace `=`, `+`, `@` and `-`, with an apostrophe. **Negative numbers therefore export as text too**; retain the original data for subsequent numeric work rather than assuming a protected export will parse as numbers.

Markdown support is deliberately limited: simple inline links/images, checklist markers and ATX headings, with fenced/indented code excluded and matched inline code excluded from link inventory. Reference links, HTML, autolinks, titled links and nested destination parentheses are outside the link subset. Classification does not prove a target safe or reachable. Redaction only replaces configured literals, longest match first, without rescanning replacements; it does not discover secrets. See the [browser report](feature-expansion-browser-2026-10-22.md) for precise subsets and refusal behavior.

Reindex uses an HMAC-authenticated **five-minute review token** tied to the actual reviewed snapshot, policy, namespace, filters and original input cursor. Apply revalidates within its transaction; changed or expired reviews return 409 before enqueue. The UI consumes review on every apply attempt. After a conflict or uncertain response, explicitly inspect and preview again; there is no automatic preview/apply retry. Abandonment and delivery cleanup likewise require separate actual previews and apply only preview-eligible IDs. See [reindex source](../apps/web/src/lib/resource-controls-reindex.ts).

Abandonment does not immediately delete objects or refund daily upload usage; ordinary cleanup follows reservation/reference rules. Budget preflight reserves nothing and cannot guarantee later admission. Acknowledgement and snooze do not resolve alerts. Deleting failed delivery history removes its retry opportunity. Pagination is live continuation: an empty filtered page can still have a next cursor.

API integrations use `/api/v1/platform/operations` and the [typed contracts](../packages/contracts/src/operations.ts); the [server report](feature-expansion-server-2026-10-22.md) lists methods and routes. Use read-only JSON `POST /index`, `POST /uploads` and `POST /retention/references` for path-sensitive reads. The platform's 16 KB URL limit cannot carry some valid maximum-length CJK paths; canonical POST bodies retain the **16 KiB** body envelope. GET remains supported when its URL fits. These reads retain authorization, accounting and metrics; they do not trigger background dispatch. The current [handler](../apps/web/src/lib/resource-controls-api.ts) sets `Cache-Control: private, no-store` on successful Operations responses; the prior header finding and all21 actual Operations integration cases passed; final-artifact verification remains pending.

Capture inventories before and after work for an offline metadata comparison; capture is not an atomic namespace snapshot and a shallow depth intentionally omits descendants. Export selects inventory files, pins downloads to recorded ETags and rehashes completed local files before skipping them. It does not restore empty folders or folder metadata. Copy uses separate clients/credentials and defaults to create-only at the destination. Text publication skips identical content and content type; JSON transforms invoke the callback once and never rerun it after a version conflict.

The CLI JSON command is **RFC 7396 merge patch**, distinct from the browser's JSON Patch operation list: null removes an object member and top-level null replaces the document. Client JSON uses JavaScript/Python's ordinary numeric representation, not the browser's exact-number parser; invalid/non-finite values are refused. Streams emit checkpoints after complete lines/records, and changes emit them after complete batches. Persist only after processing; exactly-once side effects require application-owned atomic processing/checkpoint storage. Expired change history surfaces 410 without polling or a full-scan fallback.

Draft staging validates all changes before creation, stages sequentially, and never approves/applies. Managed runs invoke work once and complete only on success. Errors retain acknowledged resource IDs, confirmed progress and original causes; an unacknowledged creation cannot supply a recovery ID. A lost commit/completion response may leave completed remote work. Inspect before retrying; conditional conflicts never become unconditional overwrites. Webhook verification checks exact raw bytes and rotating signatures locally; consumers still deduplicate event IDs within the accepted replay window.

Scopes require a static/resolved token; resolve OAuth before entering them. Nested scopes consume the outer budget, and retained clients/iterators cannot outlive it. Cancellation stops further owned requests and readers cooperatively. Python retains synchronous HTTP with its existing 30-second request timeout and **has no new scope/deadline API**; close generators when stopping early. Python workflow diagnostics preserve Ctrl+C recovery data and native `SystemExit` semantics. See [client recovery behavior](feature-expansion-clients-2026-10-22.md).

Durable CLI capture/export/bundle operations require **Linux, `/proc/self/fd` and `O_NOFOLLOW`**; protected local checkpoint/document reads also currently require Linux. Export additionally requires filesystem hard links for atomic create-only installation. Unsupported platforms fail explicitly. Offline `inventory diff` and remote line/record/change consumption without local checkpoint input remain portable. Descriptor/inode checks refuse traversal and symlink substitutions, but do not isolate processes with the same user authority or promise fsync durability.

Export and bundle checkpoints are separate from content commits. A crash between them can leave an untracked local file or a committed remote version; resume then reports a conflict for inspection. Bundles neither mirror/delete directories nor create destination folders. Their dry-run hashes local sources with zero auth/network requests and no job-state writes. Complete-part digest and local-content revalidation deliberately add bounded read/hash work to avoid trusting stale completion flags.

## Cost evidence and what remains unmeasured

The [cloud cost audit](feature-expansion-cloud-cost-2026-10-22.md) obtained one production D1 metadata snapshot: **884,736 bytes and 66 tables**, before this release. It obtained **no production CPU, memory, request/queue/R2/container usage or billing totals**. There is no demonstrated overspend or dollar saving. Worker memory percentiles are available in the platform but were not collected here; the audit links Cloudflare's [memory-metrics announcement](https://developers.cloudflare.com/changelog/post/2026-06-30-memory-usage-metrics/).

Local SQLite VM counts are not Worker CPU, SQLite `total_changes` are not billed D1 rows, and Node heap/RSS is not Worker isolate memory. Projections trade repeated reads for writes/storage: the historical file/metric fixture changes 6,000→13,033; twelve cleanup indexes add 5,000 VM and 65,536 local page bytes without changing that row counter. The final explicit-parent access fix preserves parent/child/R2/queue caps at a maximum 157 SQL / 64 trips, measured 137 / 44 and1,830 changes. One-row stale child statistics can still cause an inherited implicit `upload_parts` FK scan; four observations are separately documented. No schema expansion or universal SQLite-VM/Worker-CPU bound is claimed. Final author evidence is 86 focused tests and 72 targeted benchmark cases, independently cleared by narrow R6; the inherited FK limitation remains explicit. Migration index creation/backfills remain one-time source-wide work with unmeasured production cost; per-turn caps do not eliminate total backlog work or physical-retention delays.

The audit cites primary [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/) for indexed-write/storage charges and [Workers limits](https://developers.cloudflare.com/workers/platform/limits/) for the 128 MB per-isolate memory envelope, shared by concurrent invocations. Bounded bodies can coexist with decoded strings, parsed objects and runtime buffers; multiple uploads can each hold an 8 MiB server part buffer. No process-memory ceiling or account-wide cost cap follows from a per-operation limit.

Existing web, preview and CIMD deployment configurations are unchanged. The minute cron and required maintenance remain enabled; CIMD retains its single-`lite` maximum and idle shutdown behavior. No new paid service or CPU-limit override is introduced. These facts do not establish runtime uptime or actual spending.
