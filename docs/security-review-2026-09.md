# Security review — September 2026

Reviewed the server request boundary, scoped API and OAuth credentials, workspace membership, idempotent mutations, upload/download and preview paths, sharing, outbound requests, and dependency advisories. This is a targeted code and regression review, not a claim that every possible vulnerability has been excluded.

## Fixed findings

| Finding                                                       | Impact and fix                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workspace metadata escaped token scope                        | A personal or workspace API token could list its actor's other workspace names, identifiers, roles, and settings. Listing now requires a browser session, matching workspace creation and switching. Scoped tokens retain access to resources in their assigned namespace.                                                                                                                                                                                                                            |
| Removed credentials became usable after reinvitation          | Removing a member previously relied on the live membership check alone. Reinviting that person could make their old workspace credentials valid again. Removal now revokes their workspace token records and deletes membership in one atomic D1 batch. OAuth grants use these same records; rotation aliases respect revocation. The owner and other members' credentials are preserved.                                                                                                             |
| Idempotent requests bypassed bounded JSON parsing             | Mixed-case JSON media types skipped the early request limit, and unsupported media types could reach an unbounded body clone before route validation. The boundary now recognizes JSON consistently; idempotency consumes one bounded stream, validates the object/path before reserving a key, and passes a readable reconstructed request onward. All parsed bodies are limited to 16 KiB, including unsupported media types. Small unsupported payloads return 415; oversized payloads return 413. |
| Malformed encoded URLs escaped the error boundary             | Invalid percent escapes previously threw before normal error handling. They now return a controlled 400 response with the usual security headers. Invalid JSON roots likewise return 400 before creating an idempotency reservation.                                                                                                                                                                                                                                                                  |
| Vulnerable image-processing dependency in development tooling | The installed Cloudflare toolchain pulled in sharp 0.35.2, affected by the high-severity libheif advisory [GHSA-rgj7-g3m4-5g8c](https://github.com/lovell/sharp/security/advisories/GHSA-rgj7-g3m4-5g8c). The workspace override and lockfile pin vulnerable resolutions to patched sharp 0.35.4. This was a local tooling dependency finding, not a demonstrated production Worker code-execution flaw.                                                                                              |

## Verification

- Dependency audit: no known vulnerabilities after the lockfile update.
- Repository unit tests, builds, and TypeScript checks pass; web tests include 158 cases.
- The disposable Workers integration suite passes. Its new security boundary suite exercises 32 checks covering scoped listing, owner protection, removal and reinvitation, token aliases, fresh credentials, unsupported and oversized payloads, invalid JSON roots, malformed URLs, and successful idempotent replay.
- Existing HTTP security, features, platform, OAuth, sync, recovery, browser tools, SDK OAuth, CIMD, and queue indexing checks remain enabled and pass.

No new service, database migration, or public SDK release is required. API clients that previously listed workspaces with bearer tokens must use the signed-in browser workspace switcher; bearer credentials remain bound to their selected workspace.
